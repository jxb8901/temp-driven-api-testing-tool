# HTTPHelper runtime design

The `att-config/v2.12` loader resolves the selected profile's `httphelpers` list before external execution, validates each `att-httphelper/v1.1` descriptor and builds a case-insensitive logical registry. Profiles replace whole lists, not individual properties. The configured helper is immutable; authentication values and trust-store passwords are transport state, not expression Context.

`UnifiedTemplateEngine` routes primary `http.<id>.<operation>` calls to one run-owned `HttpHelperExecutor`. Each logical helper owns a lazily created, thread-safe Apache HTTP client and a bounded pooling connection manager. Normal runs own one executor per suite; load iterations share one executor through `LoadRunResources`; debug owns one per invocation. Each owner closes its executor at lifecycle end. There is no implicit cookie store or automatic request retry.

The executor resolves and validates the relative path, query, headers and payload before network I/O. The Action deadline caps pool/connect/read waits; an over-deadline return is classified as `HTTP_TIMEOUT`. Redirects are manually bounded and same-origin only. The operation boundary returns an `ActionExecutionResult`: a native typed body inferred from response media type in `result`, safe HTTP fields in `outputMetadata`, redacted metadata-only evidence, and an HTTP-specific diagnostic for failures. Action `result.format` is a downstream serializer only; it cannot reparse the body, and `raw` is not a common result format. Response header names are normalized to lowercase for case-sensitive Context lookup; value redaction is restricted to secret-bearing headers and known secrets. The Action runner owns assertion, persistence and retry semantics. A received 4xx/5xx is a successful transport exchange so an author can assert it; transport/format failures are `ERROR`.

Legacy descriptor validation uses `SchemaFiles` to resolve named current schemas from `schemas/` and known old schemas from `schemas/history/`. `SchemaMigrationGuidance` verifies against the declared schema first, then probes the current schema with only `schemaVersion` changed. It recommends a version bump only when that probe succeeds, preserving the original validator violation and YAML source location. Existing targeted `renderAs`/`saveAs` mappings remain authoritative.
