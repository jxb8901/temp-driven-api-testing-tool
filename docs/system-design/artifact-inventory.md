# Private artifact inventory

Completed Job archive publication walks the private output tree without following symlinks. Before accounting against the 50,000 candidate limit, it prunes exactly `load/<run>/.exec-id-reservations`, the historical per-iteration LOAD identity namespace. Only real directories at that position qualify. Case aliases, links and similarly named directories elsewhere receive the ordinary untrusted-path checks and limits.

The pruned namespace is never eligible for publication, including files with otherwise supported extensions. It creates neither manifest entries nor omissions. Pruning does not delete historical files; completed-Job retention owns their removal after Worker cleanup. Other paths, including directories and unsupported files, consume the candidate budget. A directory at depth 64 fails closed. Unreadable paths and traversal errors abort publication.

The inventory keeps the existing candidate, path, type and size limits. Artifact producers protect sensitive content before writing into the private output tree. The archive validates bounded UTF-8 text and packages the captured producer bytes without redacting text or rewriting HTML. New archives use the `att-export-approved-bytes-v1` policy with `preserved` entry decisions. The verifier still accepts historical `att-export-safe-text-v2` manifests for compatibility, but validates and returns their stored ZIP bytes without applying another sanitizer pass. See `ArtifactInventoryTest` for the 100k-file historical fixture, exact classification, candidate boundary and depth limits.

## Bounded producer-byte staging

After path and file validation, publication retains up to 8 MiB of producer bytes in memory per writer. Bytes that do not fit spill to the existing private export directory. The cap covers retained payload bytes, not JVM RSS or total allocations; the existing single-entry buffer can still reach the unchanged 16 MiB entry limit. The 128 MiB aggregate, 10k-entry and manifest limits remain enforced before publication. Publication never buffers the whole maximum-size archive.

Pass 2 consumes only those captured snapshots, from memory or spill, after the complete approved path set is known. It never rereads Worker files. Relative links and all other HTML bytes remain unchanged, including links to files omitted by archive limits. SHA-256 and CRC describe the exact producer bytes in each ZIP entry; full archive verification, file fsync and atomic replacement are unchanged. Source mutation after capture cannot replace the archived bytes. Failed attempts remove temporary exports and staging ZIPs through the same cleanup path.

Additional bounded archive metrics are `temporaryExportFiles`, `temporaryExportBytes` (producer bytes written to spill and subsequently read once), and `memoryExportPeakBytes` (retained producer-byte high-water mark). These contain no filenames or content. Historical metrics lacking these fields are unavailable, not zero. `ArtifactArchiveTest.cappedMemoryAndSpillPublishExactlyTheSameProducerSnapshot` compares both storage paths, including exact-byte preservation, later source mutation, omissions, manifest/digest/CRC verification and staging cleanup. The explicit `ArtifactPipelinePerformanceBenchmark` records reproducible small/large publication measurements.
