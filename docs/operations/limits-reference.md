# ATT Internal Limits Reference and Capacity Matrix

This reference lists capacity boundaries across Engine, Worker, Server, artifact publication, and Studio. The authoritative machine-readable inventory is [internal-limits-inventory.json](internal-limits-inventory.json). Existing safety limits remain unchanged; address pressure first with bounded responses, pagination, smaller evidence policies, and approved artifacts.

**Inventory schema:** `att-internal-limits/v1`; entries: 93.

## Outcome taxonomy and interpretation

`EXECUTION_ERROR` means execution failed; `SUBMISSION_REJECTED` means admission rejected the request; `ARCHIVE_FAILED` and `ARTIFACT_OMITTED` describe publication outcomes; `DATA_TRUNCATED`, `HISTORY_EVICTED`, and `METRICS_SAMPLED` describe bounded data presentation or retention. These classifications do not rewrite execution `status`, `exitCode`, threshold verdict, or archive lifecycle. An unavailable measurement is not zero.

## Operational triage

| Symptom / diagnostic | Subsystem | Safe remediation |
|---|---|---|
| `HTTP 413` / oversized request or inspection response | Server admission / inspection | Narrow the request; use pagination, filters, and bounded source excerpts. |
| `ATT-RESOURCE-LIMIT` / HTTP 413 | Engine package inspection | Narrow the scan or split the Package; this deterministic limit does not need an unchanged retry. An oversized workbook instead returns HTTP 200 with a partial index and that suite marked invalid as `ATT-RESOURCE-CASE-INVALID`. |
| `HTTP 429`, `503`, or `504` | Server queue / inspection / SSE | Reduce submission bursts; retry only transient queue saturation after capacity releases; inspect inspection deadline and SSE observer limits separately. |
| `ATT-ARCHIVE-NOT-READY` / 409 | Artifact publication | Refresh archive status while it is PENDING or ARCHIVING, then open after READY; only FAILED is an archive failure. |
| `DB_POOL_TIMEOUT`, `MQ_POOL_TIMEOUT`, `HTTP_POOL_TIMEOUT` | Engine helper pool | Inspect active / idle / waiting / timeouts independently; first reduce contention and hold time. |
| `*_RESPONSE_TOO_LARGE` | Engine DB / MQ / HTTP | Project fields, paginate, or reduce evidence before considering an in-range setting change. |
| `ATT-WORKER-EVENT-TRUNCATED`, `ATT-JOURNAL-EVENT-TRUNCATED` | Worker / Journal transport | Use the compact result as primary; fetch approved detail from archive or paginated history. Truncation alone is not ERROR. |
| `ATT-LOAD-EVIDENCE-QUOTA` | LOAD evidence | Inspect skipped evidence counts. Aggregate metrics remain complete; first narrow evidence selection or adjust sampling. |
| `LOAD_REPORT_WRITE_FAILED` | LOAD report publication | Execution status and exit code stay unchanged; reduce detail budget use or retry when storage is available. |
| `ATT-ARCHIVE-LIMIT-EXCEEDED` or `ATT-ARTIFACT-OMITTED` | Artifact publication | Inspect FAILED archive state or omission manifest separately; execution status does not change. |
| `METRICS_SAMPLED` / incomplete bucket coverage | LOAD metrics | Interpret charts with observation count, sample count, and coverage window. Full long-duration charts need a separate design. |
| `ATT-VALIDATION-LIMIT` | Validation budget | Use selected scope, narrow the dependency closure, and preserve partial-coverage diagnostics. |
