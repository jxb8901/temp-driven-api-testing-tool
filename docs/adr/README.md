# Architecture Decision Records (ADR)

ADRs record major technical decisions, the alternatives considered, migration implications, and unresolved questions. An ADR is **not** a declaration that a proposed feature has shipped; public behavior remains governed by the current [Reference](../reference/README.md).

## Status conventions

- **Proposed:** Design under review; field names and implementation details may still change.
- **Accepted:** Reviewed direction and key invariants agreed; acceptance does not itself imply implementation.
- **Superseded:** A later ADR explicitly replaces the decision.

Keep rationale and consequences in the ADR; use linked GitHub Issues to track implementation, tests, documentation, and release acceptance. Avoid treating future-schema examples as supported configuration.
