# ATT Server REST API v1

## REST API

所有 endpoint 位於 `/api/v1`。除 SSE stream 及 artifact 下載外，請求與回應均使用 JSON。

> **規劃中，尚未納入 ATT 4.2.7：** `POST /api/v1/validation` 是擬議的同步唯讀 validation endpoint，並非下方 Current route。詳見[規劃中的 Validation API](validation.zh.md)。目前 path-based validation 請提交 `POST /api/v1/jobs/validate`；該 endpoint 會建立 Job。

## Monitoring 及 Archive 摘要

`GET /monitoring` 會以 `Cache-Control: no-store` 回傳 `att-monitoring/v1` schema。active local `USER` 或 `ADMIN`，或具 monitoring-operator/system-administrator capability 的 container role 可讀取。明確列出的 snapshot 包括 JVM/process、Worker/admission、HTTP/API latency、event journal/compaction、storage/artifact、inspection、execution pool、schedule 及有界 job 狀態量度。`activeCompactionFailures` 是目前作用中 Job 的 aggregate；`compactionFailuresSinceStart` 是此 Server runtime 的累計值，Studio 會使用它計算 interval delta，避免 Job 退出後 alert 基準下降。HTTP 狀態及 compaction 計數是此 Server 執行期間的累計值；Studio 會從相鄰 snapshot 計算請求速率及失敗增量。歷史只保留於目前頁面，最多 96 個 snapshot。Server 最多會快取 aggregate snapshot 一秒，以限制資料庫及量度讀取。無法支援或無法取得的量度會是 `null`；目前不會量度 process RSS 或 SSE 重連／錯誤數。Filesystem 數值代表 `server.dataDir` 所在的整個 filesystem，並非只計 data directory。Job storage quota 不包括 H2 或所有 artifact／暫存寫入。回應不含 secret、filesystem path、request body 或 event 內容。`/metrics` 仍是獨立的原始 endpoint，並要求 system-administrator 權限。

`GET /monitoring/jobs/{jobId}/journal` 會執行相同 monitoring 授權及工作存取檢查。只會回傳仍作用中或已快取 Job journal 的安全有界量度。`metricsAvailable:false` 表示該工作量度未有快取；此 route 不會讀取或解析終止工作的大型 journal 檔案。要開啟事件歷史，請使用已授權的 Job Events 頁面。

`GET /jobs/{jobId}/artifacts/status` 回傳發佈狀態及精簡摘要，例如已核准／省略數量、安全的省略類別，以及只有在已核實發佈 archive 後才提供的 report path。Endpoint 為 private、`no-store`。發佈期間會寫入摘要 metadata；讀取此 route 不會列舉 archive index，也不會開啟報告內容。缺少版本化摘要 metadata 的舊 archive 會標示為 unverified，並不會產生已核准報告連結。

排程停用時，相關 endpoint 會回傳 `404`。啟用後，已驗證 caller 預設需要 `server.authorization.userRole`（`ATT_USER`）或 active local `USER` 帳戶；`ADMIN` 不具排程操作權限。Browser/API 狀態變更請求亦會套用同源檢查。建立排程的 JSON 範例如下：

```json
{
  "name": "Nightly checkout load",
  "packageId": "payments",
  "scenario": "load/checkout.yaml",
  "config": "config/config.yaml",
  "environment": "SIT",
  "timezone": "Asia/Hong_Kong",
  "cron": "0 2 * * *",
  "load": { "duration": "10m" },
  "maxConcurrentRuns": 1,
  "enabled": false
}
```

如要排程已驗證的 UI draft，請用 `draftId`（`A...` Advanced Load ID 或 `L...` Quick Load ID）取代 `scenario`，並提供驗證時使用的相同 `environment`。此方式只適用於建立排程；之後不可替換已保存的 snapshot。

Preview endpoint 只檢查 recurrence 並計算執行時間；不會驗證 package scenario、Testdata 或已保存的 draft。`POST /load-schedules` 會在保存前驗證完整 scenario 及 target closure。驗證拒絕會以 HTTP 400 回傳 `error` 及 `diagnostics` 陣列。每項可用診斷可包括 code、summary、detail、field、source file 及行/欄位置、package ID、environment、resource/target ID 和 suggestion。頂層 `requestId` 亦會複製到每項診斷。Server API 路徑淨化獨立於本機 CLI 路徑顯示旗標：package 內檔案會保留安全的 package-relative 路徑（例如 `load/scenario.yaml`）及 source 行/欄位置；package 以外的絕對路徑則顯示為 `$EXTERNAL/<basename>`。UI 會在排程編輯器旁顯示這些資料，並可將焦點移至相符欄位或開啟已保存的 snapshot。

排程預設為 paused。建立、編輯及恢復時會按目前時間計算下一個符合的 instant。Occurrence 狀態為 `scheduled`、`submitted`、`skipped` 及 `failed-to-submit`；job 執行結果仍使用一般 job API。刪除排程會移除定義，但保留歷史，也不會取消已接納的工作。刪除前請記下 UI/API 顯示的 schedule ID；只要仍有保留記錄，active USER 在定義刪除後仍可使用 `/load-schedules/{scheduleId}/executions` 讀取歷史，即使該排程不再出現在 UI 或 schedule list。History 受 `maxExecutionsPerSchedule` 限制；處理中 occurrence 及連結至執行中工作的 occurrence 可暫時超出上限，相關工作進入 terminal 狀態時會執行 pruning，schedule 定義刪除後亦會如此。

使用穩定 package ID 及該 ATT Worker command 的欄位提交工作：

```http
POST /api/v1/jobs/run
Content-Type: application/json

{"packageId":"payments","all":true,"principal":"Bob"}
```

選填的 `principal` input 只會在匿名模式使用。請求傳送原始值；Server 會自行加上 `(anonym)`，並將結果存入既有的 `principal` property。省略時仍使用 `anonymous`。

API 會回傳 `202 Accepted` 及 job ID。工作狀態依序為 `QUEUED`、`PREPARING`、`RUNNING`，最後為 `PASS`、`FAIL`、`ERROR`、`INVALID` 或 `CANCELLED`。容量已滿時會回傳 `429` 及 `ATT-SERVER-CAPACITY-EXCEEDED`。錯誤使用包含 `code`、`summary`、`detail` 及 `requestId` 的 `error` 物件；Server 不會回傳 stack trace。

啟用 `server.inlineLoad.enabled` 前，瀏覽器 Quick 及 Advanced Load endpoint 會回傳 `403 ATT-SERVER-INLINE-LOAD-DISABLED`。超出已啟用上限的 scenario 會回傳 `400 ATT-SERVER-INLINE-LOAD-LIMIT`，摘要會指出超出的設定，且 scenario 不會進入佇列。

工作記錄在有量度數據時會加入 `performance` 物件。`performance.timings` 使用 monotonic clock 記錄 admission、佇列等待、Worker 準備及啟動、Worker-ready（首個 `STATUS`）、execution-ready（首個 `PROGRESS` 或 `LOG`）、Worker 存活時間及結果至終止時間。`performance.worker` 記錄隔離 Worker 的 Heap、live thread、GC、process CPU 及抽樣 RSS 峰值。抽樣由事件觸發，每 100 ms 最多一次，可能漏掉短暫峰值。RSS 只在 Linux `/proc` 系統提供。Worker 資源數據會保存在標準工作記錄，Server 重啟後仍可讀取。

`GET /jobs` 回傳最近 100 項工作。可加上 `?principal=<text>`，在既有 `principal` property 內作不區分大小寫的文字搜尋；搜尋會在 100 項上限前執行，並採用子字串比對，因此搜尋 `alice` 亦會匹配 `alice(anonym)`。Web UI 及 `att remote jobs --principal <text>` 均使用此篩選。舊紀錄保留原有值，包括先前的 `anonymous` 紀錄。系統不會保存提交 payload，只保存 command 及 package ID 摘要。Engine result 及診斷會作為控制平面 metadata 保存。較大的報告、log 及其他證據會留在工作輸出目錄。

Studio Jobs 頁亦可按 `submissionSource`、`executionPrincipal`、`scheduleOwner` 和 `triggeredBy` 篩選。每個身份篩選支援 `all`、`text` 及 `mine`；篩選會由 Server 在分頁前執行。Job row 會新增不可變 submission provenance，同時保留舊 `principal` 欄位。詳見[Job 與 Schedule 操作](../../operations/server-jobs-schedules.zh.md)。

`GET /auth/me/preferences` 會為 authenticated account 回傳 `available`、`language`、`theme`、`version` 及 `updatedAt`；停用驗證時回傳 `available:false`。`PUT` 接受部分 `{"language":"browser|en|zh-Hant","theme":"system|light|dark"}` JSON object。請求必須有 authenticated identity、JSON、same-origin checks，並對 cookie authentication 使用既有 CSRF protection。選填 `migrateIfAbsent:true` 會保留已儲存的帳戶值，再匯入舊 browser 偏好。不接受 caller 提供 identity。值保存在 Server H2 state；anonymous deployments 僅使用 browser 偏好儲存。

資源探索可用 `case`、`template`、`flow` 或 `tool` 篩選。每頁預設 50 項，最多 100 項；續頁 cursor 會加密並綁定 Server 解析出的身份及查詢。匿名模式下所有 caller 共用同一 cursor 身份。若 package 內容改變，舊 cursor 會以 `409` 拒絕。Explorer 回傳邏輯資源 ID、安全投影、來源資訊、關聯及穩定診斷碼。YAML source 是解析及淨化後的投影，並非原始檔案內容。預設 `safe-package-files` policy 會在無須逐檔 allowlist 的情況下提供合資格、有界的 package-local Tool 文字；`allowlist-only` 則要求 `server.inspection.safeTextSources` 內完全相同的 package-relative 路徑。External scripts 必須位於已設定的 external root，並列入該 package 的 canonical 精確 allowlist；回應不會返回其 filesystem path。denyGlobs 對 package 檔案比對 package-relative path；對 external 檔案則比對相對於最具體 canonical external root 的路徑。Template/Flow 或 Configuration source 內安全的 `&{...}` 引用可透過有界 source route 讀取合資格的 package-local 文字；Server 會確認 canonical path 留在 package root，檢查副檔名、deny path、文字編碼、大小及 visibility rules，並使用綁定 package 和 origin 的 Server 不透明 `referenceId`。獨立 Configuration source route 會對 `config/` 下的合資格文字套用相同 visibility policy，並不會提供通用檔案系統瀏覽器。Resource source route 不會提供原始 config、Testdata descriptor 或 Debug sidecar；合資格且非敏感的 configuration 和 Testdata 文字可透過 Configuration route 讀取。憑證及個人資料值一律受保護。探索程序不會執行 Tool，也不會暴露檔案系統瀏覽器；檢查佇列、Worker heap、逾時及 response 大小均與一般工作執行分開限制。
