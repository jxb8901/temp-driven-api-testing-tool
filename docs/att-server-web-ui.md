# ATT Server Web UI

ATT Server bundles a static browser console at `<Tomcat context path>/ui/`, for example `https://host.example.com/tools/att/ui/`. Use a maintained Chrome, Edge, or Firefox release. The same Tomcat container authentication protects `/ui/*` and `/api/v1/*`; the UI does not create accounts or collect credentials. For authenticated deployments, use HTTPS. HTTP Basic credentials are handled by the browser and are not stored by ATT.

The console lists configured logical package IDs and recent persisted jobs. Select a package to submit Run, Debug, Load, or Validate requests, then open a job to follow progress, inspect terminal results and safe diagnostics, cancel an active job, or download logical artifacts. Inputs for package resources are logical paths relative to the selected package. The UI never accepts or displays `PACKAGE_ROOT` or Server storage paths. Artifacts are downloaded as attachments; the UI does not render artifact HTML. Direct job links such as `/ui/jobs/J10045` redirect to the canonical hash route, which reloads the job from the public API and SSE.

The Package Resource Explorer lists configured Cases, Templates, Flows, and Tools by package-scoped logical resource ID. It supports type and text filters, encrypted pagination cursors, resource details, and safe references. Source is available only when its package-relative path is listed in `server.inspection.safeTextSources`; YAML is returned as a recursive structural projection that hides free-form values, and Tool script text is redacted. Case details show identity and stage/template metadata but hide workbook business values. Reverse references include at most 100 inline entries plus an exact count and `referencedByHasMore` flag. The Explorer does not browse arbitrary files, execute Tools, or modify package content. If a package changes during pagination, the Server rejects the stale cursor and the UI can refresh the list.

Debug is available from a selected Template, Flow, or Tool detail. The form loads safe defaults from the target's optional `debug.yaml`; if it is missing, the Server supplies valid empty `att-debug/v1.2` defaults. Package-authored values are hidden by default. A `$attDebugKeepDefault` marker retains a hidden value when left unchanged; replace it with an explicit value to override it. Edit nested values as JSON objects, reset to the loaded defaults, validate, and review the redacted YAML preview before starting Debug. All targets use `inputs`; Template and Flow also use `vars`, while Tool uses `arguments` and does not accept `vars`. The Server binds each in-memory draft to the authenticated Principal and current package revision. Drafts expire after 10 minutes and are invalidated by a Server restart. Editing or submission never writes a package file. The original path-based Debug API remains available to compatible clients.

Browser-created Quick and Advanced Load are disabled by default. A Server administrator must set `server.inlineLoad.enabled: true` and configure server-owned workload, target, user, rate, concurrency, and duration caps before those forms can create drafts. The UI reads `inlineLoadEnabled` from `/api/v1/version` and disables the Advanced Load entry and hides Quick Load when the feature is off; direct navigation displays the disabled state. A disabled endpoint returns `403 ATT-SERVER-INLINE-LOAD-DISABLED`; an over-limit draft returns `400 ATT-SERVER-INLINE-LOAD-LIMIT` with a summary naming the exceeded setting. This switch does not disable existing path-based Load clients.

Quick Load is available from the same target details. Choose Virtual Users or Arrival Rate, edit the target's safe business inputs, adjust model pacing, and optionally list additional package-relative Load-level Testdata descriptors separately. The form warns when it omits Debug-local Testdata imports; those imports are never promoted implicitly. The Server reads the matching `load/load.visualuser.yaml` or `load/load.arrivalrate.yaml` policy when present; otherwise it uses a bundled 10-second low-intensity fallback. Review and confirm before the UI submits traffic. Quick Load copies only `inputs`, `vars`, or Tool `arguments`; it does not copy Debug case/stage fields or Debug-local Testdata. The Server binds the draft to the authenticated Principal and current package revision and submits the same immutable scenario that it validated.

Advanced Load is available from each package on the home page. Choose `virtualUsers` or `arrivalRate` before adding workloads; the selected model applies to every workload. Set a shared timing envelope, optional seed, package-relative Testdata imports, execution defaults, aggregate thresholds, and evidence policy. Add, duplicate, reorder, or remove workloads. Each workload has its own intensity, target, Testdata policy, and thresholds. A workload uses one Template, Flow, or Tool target, or a weighted target mix for Virtual Users. Arrival Rate workloads use one target each. Target sidecar defaults contain only safe business fields; Debug `case`, `stage`, and local Testdata are not copied. Validate the full scenario, review the safe YAML, then confirm before the Server submits its immutable draft through the normal Load scheduler. Copy and export are available only when the preview is not redacted.

The Configuration Explorer shows declared configuration, Engine-resolved configuration grouped by section, and a paged field-level comparison of two profiles. It uses the package's normal `FrameworkConfigLoader` selection rules and makes no DB, MQ, HTTP, or SSH connections. Root-only packages can inspect their configured default without selecting a profile. Values that may disclose credentials or network topology are represented as hidden; the Server does not compare hidden values. The Explorer shows field state and origin, filters the selected section, and lets you copy an effective environment into the existing Run/Debug/Load form without submitting it. Tool details link to their configuration section. The Explorer shows safe helper and Tool metadata, profile inheritance or replacement, and Testdata descriptor metadata without exposing records or unrestricted YAML. Its public endpoints and paging parameters are documented in [ATT Server deployment and API](server-deployment.md#package-configuration-inspection).

The browser uses only the public same-origin `/api/v1` REST and SSE contract. REST requests and native `EventSource` use the browser's container-managed authentication. SSE reconnects use the browser's standard `Last-Event-ID` behavior; refreshing a job view reloads job state and retained events from the Server. Closing the browser tab does not cancel the job. Cancellation requires confirmation and the UI waits for the Server's terminal status.

The UI checks the Server API version before loading job data. Terminal SSE results close the browser event stream rather than reconnecting to completed jobs; live progress is shown separately from bounded event history. The authenticated static UI and API share one Tomcat security boundary.

The console is delivered as static `att-web` JAR resources under `META-INF/resources/ui/` and packaged in the Server WAR. Relative URLs support non-root Tomcat context paths without a separate frontend service or runtime Node.js dependency. The Server applies a same-origin content security policy and rejects state-changing browser requests with an unexpected `Origin`; no credentialed CORS policy is needed. Browser-rendered API text is inserted as text, and the event list is bounded to 500 entries.

The first release provides text-based inputs for fields without public discovery endpoints. Server validation remains authoritative; browser-side validation and filtering are not authorization boundaries.
